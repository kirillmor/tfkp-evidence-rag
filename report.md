# Отчёт: доказательный RAG по ТФКП

**Автор:** Морозов Кирилл Вадимович **Группа:** М05-512д

## 1. Цель и состав решения

Реализована система доказательного ответа на вопросы по теории функций комплексного переменного. Источник знаний — учебник В. В. Горяйнова и Е. С. Половинкина «Лекции по теории функций комплексного переменного» (2025). Система получает вопрос с вариантами, находит подтверждающие фрагменты учебника, передаёт их модели Qwen3.5-4B и формирует структурированный ответ: выбранные ID, краткое обоснование, ссылки на исходные блоки либо отказ при недостаточности оснований.

Решение разделено на воспроизводимые этапы: получение PDF и подготовка корпуса (`scripts/download_pdf.py`, `scripts/prepare_corpus.py`), формирование наборов вопросов (`scripts/prepare_datasets.py`), построение индекса (`build_index.py`), предсказание (`predict.py`) и оценка (`scripts/evaluate.py`). Полный сценарий запуска и экспериментов собран в `scripts/colab_run.sh`.

## 2. Корпус и разбиение на фрагменты

PDF обрабатывается PyMuPDF. Корпус строится автоматически: одна физическая страница PDF соответствует одному документу и одному исходному `block_id` вида `p_0001`, `p_0002` и т. д. Каждая запись содержит `block_id`, номер страницы PDF, раздел и текст. Такое разбиение сохраняет привязку к первоисточнику и позволяет ссылаться на фрагмент без искусственной перенумерации. Границы разделов распознаются по обозначениям параграфов и глав.

Перед индексацией текст нормализуется: удаляются мягкие переносы, склеиваются слова, разорванные переносом строки, унифицируются пробелы и лишние пустые строки. Содержательное представление формул сохраняется в извлечённом тексте. Идентификаторы блоков проверяются на уникальность, обязательные поля и непустое содержимое. Корпус и индекс не требуют ручной разметки после запуска скриптов.

## 3. Индекс и поиск

Используется гибридный лексический индекс из двух независимых компонент:

- **BM25 (Okapi)** по словам. Токенизация регистронезависимая, `ё` приводится к `е`; учитываются русские, латинские и математические буквенные токены.
- **Символьный TF-IDF** с анализатором `char_wb` и диапазоном n-грамм 3–5. Компонент сопоставляет обозначения, формульные записи и близкие текстовые формы.

Чтобы объединить разные шкалы релевантности, оценки каждого метода преобразуются в reciprocal-rank scores: документу с рангом `r` присваивается `1 / (60 + r)`. Итоговая оценка:

\[
S(d,q)=0.65\,R_{BM25}(d,q)+0.35\,R_{char}(d,q).
\]

Веса задаются в `config.json`. При сборке сохраняются документы, BM25, обученный TF-IDF-векторизатор, разреженная матрица символьных признаков и конфигурация в `index.joblib`; `metadata.json` содержит сведения об индексе и параметрах поиска.

## 4. Формирование запроса и контекста

В итоговом режиме поисковый запрос включает формулировку вопроса и тексты всех вариантов ответа. Это позволяет искать не только тему вопроса, но и характерные математические формулировки из вариантов. По гибридному ранжированию выбираются три лучшие страницы. Для каждой добавляются соседние страницы в радиусе одной страницы; повторяющиеся позиции исключаются. Таким образом, модель получает до девяти связанных постраничных блоков, а порядок блоков соответствует ранжированию и расширению контекста.

Контекст ограничен 18 000 символами. Перед обращением к модели он дополнительно подгоняется под бюджет запроса: используется консервативная верхняя оценка размера prompt по числу UTF-8-байтов с запасом на служебные токены. Если последний блок не помещается целиком, его допустимая часть подбирается бинарным поиском. Для одного запроса резервируется не более 8 192 токенов с учётом допустимого выхода модели.

В prompt явно закреплено правило работы только по переданным фрагментам учебника. Каждый фрагмент сопровождается исходным `block_id` и номером страницы PDF. Модель должна выбрать все и только правильные ID, привести короткое обоснование и сослаться максимум на четыре блока из полученного контекста. При недостатке данных требуется `abstain=true`; в этом случае `answer_ids` и `citations` остаются пустыми.

## 5. Генерация, валидация и отказ

Используется **Qwen/Qwen3.5-4B**, ревизия `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`. Модель запускается локально через vLLM с OpenAI-совместимым Chat Completions API. Параметры из `config.json`: `temperature=0.7`, `top_p=0.8`, `top_k=20`, `presence_penalty=1.5`, `max_tokens=700`, `enable_thinking=false`, timeout 120 секунд. Поиск и построение признаков выполняются локально на CPU, генерация — локальным сервером модели.

Ответ разбирается как JSON и проходит программную проверку: `abstain` должен быть boolean; ID вариантов должны входить в исходный вопрос; повторы в списках запрещены; число цитат не превышает четырёх; обоснование непустое и ограничено 1 200 символами. При отказе оба списка должны быть пустыми. При обычном ответе ссылки должны принадлежать блокам, переданным модели в контексте. Если формат не прошёл проверку, выполняется одна повторная генерация с инструкцией вернуть корректный JSON. При повторной неудаче формируется безопасный отказ.

В конфигурации установлены ограничения на вопрос: максимум два вызова LLM, суммарно 16 384 входных и 4 096 выходных токенов. Параметры одного запроса согласованы с пределом 8 192 токена. Фактические `prompt_tokens` и `completion_tokens` обязательны в ответе endpoint: при отсутствии `usage` выполнение завершается ошибкой, а не записывает оценочный расход. `dev_trace.jsonl` сохраняет число вызовов, токены, время и список найденных блоков для каждого вопроса.

## 6. Эксперименты

Все пять конфигураций запускаются на одном открытом наборе вопросов, с одной ревизией Qwen и одинаковыми параметрами генерации. `Q` рассчитывается как среднее четырёх категориальных средних. Для разрешимого вопроса используется оценка `s = A × (0.8 + 0.2 × F)`, где `A` означает точное совпадение набора вариантов, а `F` — F1 ссылок; для вопроса на недостаточность источника засчитывается корректный отказ. Учебная стоимость вопроса:

\[
C_i = input\_tokens_i + 4\cdot output\_tokens_i + 256\cdot llm\_calls_i.
\]

| Конфигурация | Accuracy | Q | Входные токены, среднее | Выходные токены, среднее | Вызовы LLM, среднее | Стоимость, среднее | Медиана latency, мс |
|---|---:|---:|---:|---:|---:|---:|---:|
| Без контекста | 0.4000 | — | 222.07 | 154.73 | 1.07 | 1 114.07 | 7 999 |
| Один BM25 RAG | 0.6000 | 0.5483 | 3 761.60 | 233.53 | 1.13 | 4 985.87 | 16 533 |
| Итоговая система | 0.5333 | 0.5117 | 3 903.87 | 181.20 | 1.20 | 4 935.87 | 15 202 |
| Абляция: без char TF-IDF | 0.6000 | **0.5617** | 3 714.87 | 192.73 | 1.13 | 4 775.93 | 14 811 |
| Абляция: без вариантов в запросе | 0.6000 | 0.5083 | 4 599.60 | 241.20 | 1.40 | 5 922.80 | 19 593 |

Эксперимент без контекста показывает точность 40% при использовании только параметрической памяти модели. Добавление поиска BM25 повышает точность на открытом наборе до 60% и даёт `Q=0.5483`. Итоговая гибридная конфигурация сочетает лексический и символьный сигналы, соседние страницы и поиск по вопросу вместе с вариантами; её итоговые показатели составляют `Accuracy=0.5333`, `Q=0.5117`.

**Абляция 1 — отключение char TF-IDF.** Остаётся BM25-поиск с расширением контекста и вариантами в запросе. На этом наборе абляция получила `Q=0.5617` и точность 60%. Это показывает, что BM25 самостоятельно формирует содержательный контекст для большинства вопросов dev-набора, а комбинирование ранжирований следует оценивать по качеству ссылок и тематическому составу конкретного теста.

**Абляция 2 — отключение вариантов в поисковом запросе.** Поиск использует только текст вопроса. Получено `Q=0.5083`, средняя стоимость 5 922.80 и медианная задержка 19 593 мс. Сопоставление с итоговым режимом (`Q=0.5117`) показывает, что включение вариантов влияет на состав найденного контекста и итоговую оценку; этот компонент сохранён в основной конфигурации.

## 7. Разбор характерных ошибок

1. **q_005 — исключительная точка и первообразная.** Модель выбрала только `C` вместо `A, B`. В trace присутствовали `p_0029`–`p_0031`, в том числе блок `p_0030` с теоремой 4.4, а также `p_0063`–`p_0065` и `p_0014`–`p_0016`. Нужное основание было найдено; при формировании ответа модель неверно интерпретировала условие теоремы об одной исключительной точке и не перенесла его вывод на оба требуемых утверждения.
2. **q_007 — интеграл от `e^z/z^3`.** Модель воздержалась от ответа, хотя правильный вариант — `C`. В контекст попали `p_0044`–`p_0046`, `p_0053`–`p_0055`, `p_0067`–`p_0069`; блоки с формулой Коши для производной и значением производной экспоненты на нужных страницах `p_0020` и `p_0034` в поисковую выборку не вошли. Случай иллюстрирует важность одновременного извлечения формулы и фрагмента, задающего производную подынтегральной функции.
3. **q_008 — теорема Морера.** Модель воздержалась от ответа вместо выбора `B`. Были получены `p_0014`–`p_0016`, `p_0063`–`p_0065` и `p_0105`–`p_0107`; страница с формулировкой теоремы Морера (`p_0035`) в контекст не попала. Причина связана с полнотой поиска по формулировке универсального условия «для любого треугольника».

## 8. Авторские вопросы, воспроизводимость и инструменты

Подготовлены восемь авторских вопросов — по два на каждую категорию: условия теорем, сопоставление фрагментов, вычисления и недостаточность источника. Для них заданы точные наборы ответов, допустимые блоки, обоснования и недостающие сведения для двух случаев отказа. Исходные описания хранятся в `tfkp_rag/data_specs.py`; JSONL-файлы создаются скриптом, что обеспечивает воспроизводимость набора.

Основная среда запуска — Python 3.11 и GPU runtime Google Colab. Скрипт учитывает профиль Tesla T4: для vLLM включён eager-режим, число параллельных последовательностей ограничено одной. Ревизия модели фиксируется commit SHA. Версии Python-зависимостей закреплены в `requirements.txt`; основные внешние библиотеки — PyMuPDF 1.24.14, rank-bm25 0.2.2, scikit-learn 1.5.2, NumPy 1.26.4 и OpenAI Python SDK 1.54.4. Для локального сервинга используется vLLM.

Внешний код и библиотеки применяются для извлечения текста PDF, лексического ранжирования, TF-IDF, сериализации индекса и OpenAI-совместимого взаимодействия с локальной моделью. Полный запуск подготовки данных, построения индекса, итогового предсказания, пяти экспериментов и тестов выполняется скриптами репозитория.
